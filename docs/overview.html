Der Pivot in einem Satz: Der Code-Worker wechselt vom einmaligen CORTEX.COMPLETE (rät, degradiert über Iterationen) zum agentischen Worker (Cortex Code Agent SDK) — der äußere deterministische Loop und das frozen-test Gate bleiben unverändert das Herz. 1.7 (Checkpointing) wurde verworfen (Recovery ist task-granular über die append-only Spur).
M3 erledigt: der agentische Worker ist im deterministischen Loop aktiv (`generate()` → Cortex Code SDK, schreibt Dateien selbst, liefert structured_output). Bewiesen: task-add → DONE, task-impossible → NEEDS_HUMAN. Gate-Integrität: visible- und held-out-Tests laufen getrennt — der Agent bekommt nur die sichtbaren als Feedback; held-out entscheidet mit, verlässt aber nie den Container. (Offener Härtungspunkt: held-out-Dateien liegen physisch auf dem gemounteten Stage — später isolieren.) Interne Identität (kein PAT), CLI gepinnt v1.1.66. Quellen: docs/COMPONENT_AUDIT.md, spec/Phase1_Orchestrator_Loop.md, docs/superpowers/specs/2026-06-28-agentic-worker-migration-design.md

Der deterministische Loop (das Herzstück)

load_taskLOCKED aus TASK_SPECS + PROJECTS-Lookup; Job läuft als ORCH_PROJ_<ID>
→
DEVELOPER-Node ✅agentischer Worker (Cortex Code SDK): schreibt/führt aus/iteriert in lokalem cwd, liefert structured_output · im Loop aktiv (M3); held-out-Tests nur im Gate, nie als Feedback
→
run_testsfrozen Tests über den Artefakt-Baum, pytest, Exit-Code+Log → TEST_RESULTS
→
gateliest nur den Exit-Code — kein LLM-Urteil
PASS → RUNS=DONE → nächster Task
FAIL → TEST_RESULTS-Feedback → DEVELOPER-Node (Loop, ≤ MAX_ITER)
≥ MAX_ITER → STOP + Report, RUNS=NEEDS_HUMAN (kein Endlos-Loop)

Zwei geschachtelte Loops: innen der Agent (Tool-Session, max_turns), außen LangGraph + frozen-Gate (MAX_ITER, die einzige „done"-Autorität). Kein Thread-Resume über Außen-Iterationen; held-out-Tests (für den Agenten unsichtbar) verhindern Overfitting.

Tragende Entscheidungen

Determinismus-Gate
Nur grüner Exit-Code = PASS. Nie „der Agent sagt fertig".
Cortex & CLI intern, kein EAI
OAuth-Token aus /snowflake/session/token; Agent-CLI nutzt dasselbe Token (bewiesen M2). Kein PAT.
Feedback-Loop = Tabellen, nicht GitHub
Läuft überall; GitHub ist nur Liefer-Artefakt (Phase 3), nie der Loop.
Tenant = Datenbank
Isolierte DBs statt RAP (operativ zu teuer). Mehrere Instanzen via .env.
Append-only + RBAC
Jede Änderung = neue Zeile; LEAD nur INSERT; keine autonomen DROPs (Versionierung + human-gated Cleanup).
Agentischer Worker (im Loop aktiv)
Cortex Code SDK statt One-Shot; interne Identität. Gate bleibt Autorität; visible vs held-out getrennt, kein Feedback-Leak; kein Thread-Resume außen.
Reproduzierbarkeit
Gepinnte Deps + gepinnte CLI-Version (Tarball+sha256). Kein „latest"-Drift.
Governance
Agents build+test; Humans own the blast radius (Account/Security/Network/DROP = HITL).
